# Training environment — AirSim Blocks (UE4) project

**English** | [简体中文](ENVIRONMENT.zh-CN.md)

The simulation environment used for every number in this repository. It is the
**Microsoft AirSim "Blocks" Unreal Engine 4 C++ project**, wrapped as
`Blocks2_AirSim170`, with the AirSim plugin built in and the training scene as its
default map.

## What is in this repository

`project/` (13.6 MB) contains the part that actually defines the **scene** — small, binary, and
irreplaceable:

| Path | Size | What it is |
|---|---:|---|
| `project/Content/FlyingCPP/Maps/FlyingExampleMap.umap` | 12.3 MB | **the training scene** — the 250 × 250 × 50 m field with the ~70 obstacle actors |
| `project/Content/Geometry/Meshes/1M_Cube*.uasset` | 0.17 MB | the cube meshes the obstacles are instanced from |
| `project/Content/FlyingCPP/…`, materials, `BP_FlyingPawn.uasset` | 0.4 MB | the AirSim flying pawn and base materials |
| `project/Blocks.uproject`, `project/Config/Default*.ini` | 4 KB | project descriptor (enabled plugins) and map/startup settings |
| `project/Source/` | 3 KB | the `Blocks` game module stub |

The obstacle layout lives **inside the `.umap`** as actor transforms over those three basic meshes
(plus Unreal's built-in cylinder / cone / sphere primitives, which live in engine content and
therefore do not appear here). That is why a scene with ~70 obstacles is only 12 MB: it stores
transforms, not geometry.

![Training scene](figures/training_scene.png)

The environment as it looks when you start it: a walled 250 × 250 × 50 m field whose ~70 obstacle
actors are drawn from slabs, pillars, cylinders, cones, pyramids, spheres and compound bodies. The
screenshot is also committed at [`figures/training_scene.png`](figures/training_scene.png).

## What is *not* in this repository, and why

The archive is 4.69 GB unpacked, of which almost none is the scene:

| Part of the archive | Size | Disposition |
|---|---:|---|
| `Intermediate/` | 2.59 GB | **dropped** — UE build cache, regenerated by `GenerateProjectFiles` + build |
| `Saved/` except `StagedBuilds/` | 0.54 GB | **dropped** — editor state, auto-saves, cooked shaders, crash reports (5 auto-saved copies of the map) |
| `Saved/StagedBuilds/WindowsNoEditor/` | 0.36 GB | **repackaged as its own artifact** — the standalone runnable build |
| `Plugins/AirSim/` | 0.68 GB | kept (minus its own `Intermediate/` build cache, 78 MB) — vendored plugin + deps, so the project builds offline |
| `Binaries/`, `Content/`, `Config/`, `Source/`, `Blocks.uproject` | 0.52 GB | kept in the project artifact (`Content/` is additionally committed to git) |

That is why the release ships **two** archives instead of one 1.29 GB blob — see below.

## How to run it

**Option A — standalone build (no Unreal Engine install needed, ~200 MB download).**
Unzip `airsim-blocks2-standalone-win64.zip`, put [`settings.json`](settings.json) in
`%USERPROFILE%\Documents\AirSim\`, and run `Blocks.exe`. This is the packaged game build that was
actually used for training, so nothing has to be compiled.

**Option B — the editor project (needs Unreal Engine 4.27, ~375 MB download).**
Unzip `airsim-blocks2-project-win64.zip`, run `GenerateProjectFiles.bat`, open `Blocks.uproject`,
press Play. This is the only way to edit the scene — but note the **multi-drone isolation patch is a
blueprint change that is not in the archive** (it lives in the UE assets), so a freshly built project
still needs it applied before training.

Either way, the **multi-drone isolation patch is mandatory** before training: with ten drones
spawned at the same point, stock AirSim has them collide with and occlude one another. See
[`README.md`](README.md#the-multi-drone-isolation-patch-mandatory),
[`ISOLATION_PATCH.md`](ISOLATION_PATCH.md) and
[`../../docs/REPRODUCING.md`](../../docs/REPRODUCING.md) §2.

## Release artefacts

The environment is **not** in git. It is repackaged from the original archive into two lean
artifacts, both attached to the
[**`v0.1.0` release**](https://github.com/MEGO0SFT/uav-drl-avoidance/releases/tag/v0.1.0)
(`Blocks2_AirSim170.zip` itself is never published, because 2.59 GB of it is build cache and
0.89 GB is editor scratch state):

|---|---:|---:|---|---|
| [**`airsim-blocks2-standalone-win64.zip`**](https://github.com/MEGO0SFT/uav-drl-avoidance/releases/download/v0.1.0/airsim-blocks2-standalone-win64.zip) | **219.4 MB** | 356.6 MB | the packaged standalone game: `Blocks.exe`, `Blocks-WindowsNoEditor.pak`, engine third-party DLLs, UE4 prerequisite installer. 25 files. Unzip → run. | `3c17b77c7c39b67576a4d800d8317402eb8a9819fce1e627b5f6b3e112371a8c` |

Together they are **594 MB**, versus 1.29 GB for the original archive — the removed 870 MB is
entirely build cache and editor scratch state, with no loss of runnable or editable content.

The project archive intentionally keeps ~640 MB that a *run-only* user does not need: native debug
symbols (`.pdb`, 422 MB) and the vendored static libraries (`.lib`, 216 MB). They are there so that
the plugin can be **rebuilt and debugged offline** without re-downloading upstream AirSim. If you
only want to open the scene, the standalone artifact is the better download.

> **Verified after repacking.** The project archive was unpacked and opened in Unreal Engine 4.27 —
> the scene loads and runs with no retarget prompt and no rebuild required, because
> `Plugins/AirSim/Binaries/Win64/UE4Editor-AirSim.dll` (the compiled plugin, 4.77 MB) is included
> alongside the vendored source. The screenshot above was taken from that build.

Start with the **standalone** one — it is what the experiments actually ran, and needs no Unreal
Engine install. Only take the project archive if you need to edit the scene.

> The multi-drone isolation patch is a **blueprint change**, and it is **included in the project
> archive** — the patched asset ships as
> `Plugins/AirSim/Content/Blueprints/BP_FlyingPawn.uasset` (identical bytes also at the project-level
> `Content/BP_FlyingPawn.uasset`), so a rebuild keeps the patch. Keep that file as it is; swapping in
> the stock AirSim pawn breaks training. The same bytes are committed to git at
> [`project/Content/BP_FlyingPawn.uasset`](project/Content/BP_FlyingPawn.uasset)
> (sha256 `0f4f91c1…`).
